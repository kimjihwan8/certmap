# 매칭 개선 기획

2026-10-21. 참고: [yeodusung-ux/korea-restaurant-certs](https://github.com/yeodusung-ux/korea-restaurant-certs)

## 참고 레포가 이미 하는 것

- 인증 8종(공공 6 + 개인 2)을 정적 HTML 한 장에 합쳐 지도·별점·내 주변 검색 제공
- 동일 가게 매칭 = ① 전화번호 같음(한 번호 9건 이상은 대표번호로 보고 버림) ② 시군구+도로명+건물번호 같음 **AND** `similar()`
- `similar()`: 특수문자·지점 접미사 제거 후 같음 / 3자 이상 부분문자열 / 글자 집합 Jaccard ≥ 0.75
- 좌표는 카카오 지오코딩(고유 주소 8.5만 개)
- 스스로 밝힌 한계: 같은 건물의 다른 식당이 한 가게로 묶임(호텔 입점 식당 등). **매칭 정확도는 측정하지 않음**

## 우리와 다른 점 (차별점이어야 하는 것)

| | 참고 레포 | 우리 |
|---|---|---|
| 매칭 대상 | 인증 ↔ 인증 | **인증 ↔ 상가 277만** (상가업소번호를 가게 ID로 사용) |
| 좌표 | 카카오 API로 지오코딩 | 매칭된 상가 좌표 (API 불필요) |
| 업종 | 키워드 규칙으로 추정 | 상가 소분류 43종 (결측 0%) |
| 매칭 품질 | 측정 없음 | **정답지 기반 정밀도·재현율** |
| 여러 소스 병합 | 전화·주소로 union-find | 같은 상가업소번호에 붙은 인증끼리 묶음 (허브 방식) |

## 지금까지 잰 숫자 (모범음식점 11,560건 ↔ 상가)

| 방법 | 매칭률 | 정밀도 |
|---|---|---|
| 같은 건물 + 완전일치 | 63.9% | 미측정 |
| 같은 건물 + 공백·괄호 제거 | 77.3% | 미측정 |
| 같은 건물 + 참고 레포 `similar()` | **83.5%** | 미측정 |

규칙만으로 83.5%. AI가 풀 수 있는 공간은 최대 16.5%이고, 그중 일부는 "상가에 없는 집"이나 "같은 건물의 다른 가게"라 실제로는 더 작다.

## 단계

### 0단계 — 정답지 (관문)

층화 표본 300쌍을 손으로 라벨링한다. 라벨: `같은 가게` / `다른 가게` / `모름`.

| 표본 | 개수 | 재는 것 |
|---|---|---|
| A. `similar()`로 붙었지만 완전일치는 아닌 쌍 | 100 | 참고 레포 규칙의 **정밀도** |
| B. 같은 건물에 식당은 있는데 `similar()`로 못 붙은 건 | 150 | 놓친 것 중 진짜 같은 가게 비율 = **AI 여지** |
| C. `similar()` 후보가 2개 이상인 건 | 50 | 1:1 선택 규칙이 필요한 정도 |

**관문 (숫자 보기 전에 확정):**
B에서 "같은 가게" 비율 × B 구간 크기 ÷ 전체 = AI 여지.
**AI 여지 < 5%면 AI 매칭은 넣지 않거나 보조로 내리고, 프로젝트 중심을 검색·대량 지도로 옮긴다.**

### 1단계 — 규칙 개선 (관문 결과와 무관하게 진행)

1. **블로킹 확장**: 지번 주소 키 추가, 주소 파싱 실패 패턴(`33- 3`, `지하911`, 붙어 쓴 `121번길20방산빌딩`) 처리
2. **이분법 대신 점수**: 이름 일치·부분문자열·바이그램 유사도·지점명 일치·업종 일관성(인증 `음식의유형` ↔ 상가 소분류)·층 정보 → 점수 → 임계값
3. **1:1 배정**: 후보가 여럿이면 최고점 하나만 (`한우촌` ↔ `한우촌판매장`처럼 정육점·판매장 오매칭 방지), 한 상가에 같은 소스 인증 2건이 붙으면 충돌로 표시
4. 임계값은 **정밀도 98% 이상**을 지키는 선에서 재현율 최대로 잡는다. 틀린 매칭(엉뚱한 가게에 인증 표시)이 빠진 매칭보다 나쁘다

### 2단계 — AI 판정 (0단계 관문 통과 시에만)

- 1단계 점수가 애매한 구간만 LLM에 보낸다: 인증 레코드(상호·주소·주된음식) + 같은 건물 후보들(상호·지점명·소분류·층) → "몇 번이 같은 가게인가, 없음"
- 정답지로 정밀도·재현율 증가분, 호출 수, 건당 비용을 잰다
- 판정 결과는 캐시해서 재실행 비용 0

### 3단계 — 여러 소스 병합

- 같은 상가업소번호에 붙은 인증 = 같은 가게 (소스가 N개여도 N개 링크로 끝남)
- 상가에 없는 인증끼리는 참고 레포 방식(전화·주소+상호)으로 보조 병합
- 참고 레포 방식과 그룹 정밀도 비교 (호텔 문제가 줄었는지)

## 결과물 서사

```
완전일치 63.9% → 정규화 77.3% → 참고 레포 규칙 83.5% → 우리 규칙 ?% → (AI ?%)
각 단계 정밀도 함께 표기
```
